# 蓝舟平台服务端开发规范 Skill (Agentic Code 指导)

## 用途

本规范用于指导蓝舟平台（BASA）的 Java 后端代码生成，覆盖架构分层、数据库设计及编码约定。所有生成的代码必须严格遵循此规范。

## 核心原则

1.  **命名**：清晰、达意。Java 遵循驼峰法则；数据库遵循小写下划线，禁用拼音。
2.  **数据**：表必须有主键、逻辑删除标识及必要审计字段。强调性能（索引）与安全（脱敏、预编译）。
3.  **架构**：严格遵循 `api`（接口定义） -> `center`（接口实现+DAO） -> `control`（控制器，SaaS 应用特有）的分层模型。

# 蓝舟平台开发规范（数据库+服务端）

本规范用于指导蓝舟平台及相关应用的数据库设计、服务端开发，确保代码和数据库的一致性和可维护性。

## 一、数据库设计规范

### 1. 命名规范

| 对象     | 前缀/规则                                | 示例                       |
| -------- | ---------------------------------------- | -------------------------- |
| 数据库   | 业务系统名\_子系统名，全小写，字符集utf8 | `ec_cms`                   |
| 表       | `t_` + 含义，全小写，下划线分隔          | `t_user_login`             |
| 字段     | 全小写，下划线分隔，布尔用`is_`前缀      | `is_delete`, `create_time` |
| 主键     | `id`，自增                               | `id`                       |
| 外键字段 | `xxx_id`                                 | `user_id`                  |
| 临时表   | `tmp_` + 表名 + 日期后缀                 | `tmp_order_20241201`       |
| 备份表   | `bak_` + 表名 + 日期后缀                 | `bak_order_20241201`       |
| 视图     | `v_` + 含义                              | `v_user_info`              |
| 序列     | `seq_` + 表名                            | `seq_order`                |
| 普通索引 | `idx_字段名` 或 `idx_字段1_字段2`        | `idx_user_name`            |
| 唯一索引 | `uk_表名_字段名`                         | `uk_user_mobile`           |
| 触发器   | `tr_` + 表名 + `_i`/`_u`/`_d`            | `tr_order_i`               |
| 存储过程 | `up_` + 动宾                             | `up_sync_order`            |
| 函数     | `udf_` + 动宾                            | `udf_get_age`              |

**规则**：

- 所有名称只使用英文字母、数字、下划线，小写，禁止拼音和驼峰。
- 长度：数据库/表/字段不超过30字符（MySQL）或128字符（达梦）。
- 禁止使用保留字。

### 2. 表设计规范

- **引擎**：MySQL统一使用InnoDB。
- **字符集**：UTF-8或UTF8MB4，建表显式指定。
- **主键**：必须包含自增主键`id`（INT/BIGINT），与业务无关。
- **时间列**：核心表必须有`create_time`和`update_time`（timestamp/datetime）。
- **逻辑删除**：表必须包含`is_delete`字段（TINYINT，默认0），禁止物理删除。
- **字段非空**：所有字段设为NOT NULL，并提供默认值。
- **注释**：表和字段必须有COMMENT，枚举值需说明含义。
- **列数控制**：单表字段数建议不超过20。
- **反范式**：允许适当冗余以减少JOIN，但需控制数据一致性。
- **大表DDL**：100万行以上的表ALTER必须审核，业务低峰期执行。

### 3. 字段数据类型规范

| 场景           | 推荐类型                                      | 说明                                |
| -------------- | --------------------------------------------- | ----------------------------------- |
| 自增主键       | `BIGINT UNSIGNED` 或 `INT UNSIGNED`           | 大表用BIGINT                        |
| 状态/类型/性别 | `TINYINT`                                     | 取值范围小，节省空间                |
| IP地址（IPv4） | `INT UNSIGNED`                                | 使用`inet_aton`/`inet_ntoa`转换     |
| 金额           | `DECIMAL(M,D)`                                | 如`DECIMAL(16,2)`，禁止FLOAT/DOUBLE |
| 固定长度字符串 | `CHAR(n)`                                     | 如密码、邮编                        |
| 可变字符串     | `VARCHAR(n)`                                  | 根据实际长度，避免过大              |
| 时间           | `TIMESTAMP` 或 `DATETIME`                     | 2038问题留意，推荐`DATETIME`        |
| 大文本/二进制  | 不存数据库，用文件存储+路径                   | 禁止BLOB/TEXT存储图片或文件         |
| 枚举           | 使用`TINYINT` + CHECK或应用逻辑，禁止ENUM/SET |                                     |

### 4. 索引规范

- **数量**：单表索引不超过7个，单个索引字段不超过5个。
- **主键**：必须自增、整型，避免UUID或业务主键。
- **联合索引**：区分度高的字段在前，遵循最左前缀原则。
- **前缀索引**：长字符串可考虑前缀索引，长度≤8。
- **外键索引**：外键列必须建索引（但业务中尽量不用外键）。
- **冗余索引**：禁止冗余索引（如已有`(a,b)`，不再建`(a)`）。
- **索引禁忌**：不在低基数列（性别）、频繁更新的列、函数/计算列上建索引。

### 5. SQL语句规范

#### 通用规范

- 禁止`SELECT *`，必须显式列出字段。
- INSERT必须指定列名。
- 大批量DML分批提交（建议每批≤2000行）。
- WHERE条件中避免函数、计算、隐式类型转换，确保能使用索引。
- 避免`LIKE '%...%'`，尽量`LIKE '...%'`。
- IN列表不超过500个值，超过则用临时表。
- 禁止在程序中执行DDL。
- 使用绑定变量（参数化查询），防止SQL注入并提升计划重用。

#### 事务规范

- 事务中SQL不超过5个（支付除外）。
- 更新尽量基于主键或唯一键。
- 避免大事务，长事务需拆分。

#### 分页规范

- `LIMIT m,n` 在m大时性能差，改用`WHERE id > last_id LIMIT n` 或延迟关联。

#### 禁用项

- `UNION` 用 `UNION ALL` 代替（除非要去重）。
- 禁止 `UPDATE/DELETE ... LIMIT`。
- 禁止子查询嵌套（尤其是关联子查询）。
- 禁止存储过程、函数、触发器、视图、事件、外键（业务逻辑移至应用层）。
- 禁止负向查询（`NOT IN`, `NOT LIKE`, `<>`）。
- 禁止在数据库内做数学运算、类型转换。

### 6. 达梦数据库特定规范

- **表空间**：每个业务用户建独立表空间，禁止使用MAIN。
- **页大小**：建议32KB。
- **大小写敏感**：推荐敏感（Oracle迁移），MySQL迁移可不敏感。
- **字符集**：UTF-8。
- **参数**：`COMPATIBLE_MODE` 根据源库设置；`CALC_AS_DECIMAL=1` 保留除法小数。
- **分区**：千万级表建议分区，分区列必须作为查询条件。
- **索引**：OLTP表索引不超过5个；重建索引用`online`；禁止`replace`修改索引。
- **序列**：必须设置CACHE（尤其主备环境）。
- **审计**：不建议开启审计，可用异步SQL日志替代。
- **用户**：分管理、应用、维护、备份四类，应用用户无DBA权限。

### 7. MySQL特定规范

- **引擎**：InnoDB。
- **字符集**：utf8/utf8mb4，统一。
- **事务隔离级别**：REPEATABLE-READ。
- **缓存**：读写比>10:1的热点数据可放入Redis。
- **分区表**：禁止使用（改用分表或应用层分片）。
- **分库分表**：单表预计超500万行或10GB时需分表。分表数≤4096，分库数≤1024。
- **主从延迟**：读敏感业务强制走主库。

## 二、服务端开发规范（Java）

### 1. 工程结构与命名

#### 包命名

- 格式：`cn.ccccltd.biz.<服务名>`
- 全部小写，点分隔。

#### 工程结构

```
api/                # 对外接口定义（service接口、BO）
center/             # 接口实现（service.impl、atom、dao、po）
control/            # REST控制器（应用层）
```

#### 类命名

- 接口：`XxxService`
- 实现：`XxxServiceImpl`
- 控制器：`XxxController`
- 原子服务接口：`XxxAtomService`，实现：`XxxAtomServiceImpl`
- DAO：`XxxMapper`
- PO：`XxxPO`
- BO：`XxxReqBO` / `XxxRspBO`

#### 方法命名

| 类型      | 命名规则                             | 示例           |
| --------- | ------------------------------------ | -------------- |
| 查询单个  | `getXxx`                             | `getUser`      |
| 查询列表  | `listXxx`                            | `listUser`     |
| 分页查询  | `listPageXxx`                        | `listPageUser` |
| 统计      | `countXxx`                           | `countUser`    |
| 插入      | `saveXxx`                            | `saveUser`     |
| 删除      | `removeXxx`                          | `removeUser`   |
| 更新      | `editXxx`                            | `editUser`     |
| DAO层方法 | `select/insert/delete/update` + 实体 | `selectUser`   |

#### 变量/常量

- 变量：驼峰，首字母小写，不用`_`或`$`开头。集合用复数。
- 常量：全大写，下划线分隔，如`MAX_RETRY_COUNT`。

### 2. 代码注释规范

- 所有类、接口、方法、全局变量必须有Javadoc注释。
- 类注释：描述、`@author`、`@version`、`@date`。
- 方法注释：描述、`@param`、`@return`、`@throws`。
- 复杂逻辑内使用行内注释。
- 注释占代码比例约20%。

### 3. 编码风格

- **缩进**：4空格，禁止Tab。
- **行宽**：≤120字符。
- **大括号**：左大括号不换行，右大括号独占一行。
- **if/for/while** 等必须使用大括号，即使只有一句。
- **import**：禁止使用`*`导入，移除未使用的import。
- **方法长度**：不超过100行。
- **文件长度**：不超过900行。

### 4. 控制流与语句规范

- `switch` 必须包含 `default`。
- 避免 `return` 中使用括号（除非必要）。
- 禁止魔法值（未定义的常量）。
- 禁止在条件语句中出现赋值操作。
- 字符串比较使用 `.equals()`，不用 `==` 或 `!=`。
- `Long` 类型初始值使用大写 `L`。

### 5. 其他开发建议

- **依赖注入**：使用setter/getter注入，禁用`@Autowired`字段注入。
- **BO对象**：实现`toString()`，添加属性注释。
- **事务控制**：业务服务层启用事务，原子服务层不启用。
- **调用外部服务**：先完成本中心DB操作，再调用外部，失败后回滚。
- **缓存**：字典类数据应加载到缓存（Redis）。
- **查询优化**：JOIN不超过3表，避免全表查询，使用EXPLAIN验证索引。
- **单元测试**：命名`TestXxx`，方法`testXxx`，使用`@Test`。
- **代码检查**：遵循CheckStyle规则，定期检查重复率、复杂度、注释率。

## 四、维护审批流程

- 数据库变更需提交《变更申请单》，邮件审批后执行。
- 审核要点：表名/字段名规范、主键自增、字符集、注释完整、数据类型合理、索引设计等。
- 数据操作文件需为UTF-8文本格式。
